# Publishing Pulso

The source module is `pulso.local/pulso`, so development builds resolve internal
imports locally without claiming a public repository or domain.

The release workflow injects `GITHUB_REPOSITORY` into
`internal/version.ReleaseRepository`. Local builds have no release repository.
You can explicitly configure one with `PULSO_RELEASE_REPOSITORY=owner/repository`.
Only use a repository you control and trust. The installer requires the same
variable. Both use GitHub HTTPS release downloads and require SHA-256 checksums.

The `pulso update` command refuses to replace the executable if checksum
verification fails. Releases must include `checksums.txt`, the platform binaries
and the platform archives generated by `.github/workflows/release.yml`.

The GitHub release workflow packages a top-level folder inside each archive;
the installer supports that layout and flat archives. No registry package,
Homebrew tap, public domain or new GitHub account has been created.

If you publish a Go module, replace `pulso.local/pulso` consistently in go.mod,
imports and linker flags with your actual module path before tagging a release.

The Nix dependency vendor hash includes the pure Go SQLite driver and its
dependencies. It is tied to `go.mod` and `go.sum`, so refresh it with
`scripts/update-vendor-hash.sh` whenever a dependency changes, then verify the
package with `nix build .` before publishing it. See the Nix package section of
[developer-guide.md](developer-guide.md).
